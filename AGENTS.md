# Работа с проектом

- Источник требований — SPEC.md; текущие решения — ARCHITECTURE.md, PERMISSIONS.md, DECISIONS.md; этапы — PLAN.md, состояние — STATUS.md.
- Пользователь принял этапы 1–2 и разрешил этап 3 из PLAN.md полностью. Этапы 4–7 не начинать без отдельной команды.
- Использовать существующий checkout; каждая cloud-задача уже изолирована. Не создавать Git worktree без явной просьбы пользователя.
- При реализации разделять models, services, selectors и HTTP; серверные права и аудит обязательны во всех точках входа. Роли и группы адресатов не смешивать. Рабочие данные только PostgreSQL.

- Проверки запускать для своего этапа; concurrency/constraints — на PostgreSQL. После этапа записывать реальные результаты и ограничения в STATUS.md. Не выдавать непроверенные шаги за выполненные.

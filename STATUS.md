# Состояние проекта

## FastAPI rewrite

HTTP runtime перенесен на `fastapi_app.main:app`, ASGI entrypoint — `config.asgi:application`. Добавлены PostgreSQL access layer, session cookie, CSRF token, login/logout, recovery/reset, смена пароля, личные задачи, карточки, чек-листы, завершение, профиль, события и чат. Шаблоны находятся в `fastapi_app/templates`, статические CSS/JS сохранены.

Старые framework-specific runtime files, views, forms, settings, migration files и management commands удалены по прямому запросу пользователя. Схема существующей базы используется напрямую SQL-запросами; для нового runtime добавляется `app_sessions` через `scripts/prepare_database.py`.

### Проверено

- FastAPI образ собирается с hash-locked dependencies.
- `uvicorn` запускает приложение.
- `/accounts/login/` отдает русский HTML и прежнюю стилистику.
- `/` анонимному пользователю возвращает redirect на вход.
- health без ключа закрыт, с ключом отвечает `ok`.
- `python3 scripts/smoke.py`: HTTP redirect/login, CSS, private health, DB readiness и SMTP через Mailpit.
- `docker compose ... exec -T web python scripts/smoke_auth.py`: вход, смена пароля с отзывом сессий, recovery-запрос и одноразовый reset.
- `docker compose ... exec -T web python scripts/smoke_admin.py`: permission gate, создание задачи, вкладки активных/выполненных, приглашение и отключение учетной записи.
- `docker compose ... run --rm tests`: compileall для `fastapi_app` и `config`.
- `pip check`, `git diff --check` и поиск удаленных framework-следов завершились без ошибок.
- Основной интерфейс «Мои задачи» дополнен согласованными фильтрами по названию/типу и сортировкой по сроку или дате события; карточки используют фиолетовый макет и красный цвет просрочки.
- Реализованы выбор исполнителей и подзадач при создании, сохранение отметок подзадач, запрет завершения задачи до выполнения всех подзадач и исключение задач, назначенных только себе, из «Выдано мной».
- Автоматическое состояние события после даты события, возврат до блокировки чата и отказ в возврате после блокировки проверены отдельным контейнерным сценарием.
- После пересборки образа пройдены `scripts/smoke.py`, `scripts/smoke_auth.py`, `scripts/smoke_admin.py`, `compileall`, рендеринг всех Jinja-шаблонов и `git diff --check`.
- Основная доска приведена к макету: вкладочная навигация, белые внутренние блоки карточек на фиолетовом фоне, отдельные колонки сроков/дат, фильтры без отдельной кнопки и адаптивная мобильная раскладка.
- Введена роль-зависимая навигация: «Выдано мной» и создание доступны только пользователям с соответствующими разрешениями; преподаватель/куратор видит личную доску без этих действий. Проверено контейнерным HTTP-сценарием.
- Профиль показывает активность и назначенные роли; ролевые проверки также применяются к прямым URL создания и просмотра выданных заданий, а не только к кнопкам интерфейса.

### Не проверено

- полный browser regression suite;
- миграция старых данных и старых сессий;
- production HTTPS/SMTP;
- роли/группы и все расширенные административные операции;
- полный browser regression suite и визуальная проверка в реальном браузере (скриншотный diff не выполнялся);
- расширенные права, квоты, аудит и конкурентные конфликты.

## Следующий блок

Базовое администрирование сотрудников и основной пользовательский workflow перенесены и проверены контейнерными сценариями. Роли/группы, расширенные административные операции, полноценная модерация и browser regression остаются следующим блоком; непроверенные сценарии не считаются готовыми.

Одноразовый bootstrap администратора добавлен в `scripts/bootstrap_admin.py` и проверен для `egorovasv@kp11.ru`; приглашение доставлено в локальный Mailpit.

Нативная схема PostgreSQL проверена на отдельной пустой базе: создаются `accounts_user`, каталог доступа, задачи, события, сообщения и `app_sessions`. Инициализация PostgreSQL на Windows переведена с shell bind-mount на SQL-файл.

# Состояние проекта

## FastAPI rewrite

HTTP runtime перенесен на `fastapi_app.main:app`, ASGI entrypoint — `config.asgi:application`. Добавлены PostgreSQL access layer, session cookie, CSRF token, login/logout, recovery/reset, смена пароля, личные задачи, карточки, чек-листы, завершение, профиль, события и чат. Шаблоны находятся в `fastapi_app/templates`, статические CSS/JS сохранены.

Старые framework-specific runtime files, views, forms, settings, migration files и management commands удалены по прямому запросу пользователя. Схема существующей базы используется напрямую SQL-запросами; для нового runtime добавляется `app_sessions` через `scripts/prepare_database.py`.

### Проверено

- FastAPI образ собирается с hash-locked dependencies.
- `uvicorn` запускает приложение.
- `/accounts/login/` отдает русский HTML и прежнюю стилистику.
- `/` анонимному пользователю возвращает redirect на вход.
- health без ключа закрыт, с ключом отвечает `ok`.
- `python3 scripts/smoke.py`: HTTP redirect/login, CSS, private health, DB readiness и SMTP через Mailpit.
- `docker compose ... exec -T web python scripts/smoke_auth.py`: вход, смена пароля с отзывом сессий, recovery-запрос и одноразовый reset.
- `docker compose ... exec -T web python scripts/smoke_admin.py`: permission gate, создание задачи, вкладки активных/выполненных, приглашение и отключение учетной записи.
- `docker compose ... run --rm tests`: compileall для `fastapi_app` и `config`.
- `pip check`, `git diff --check` и поиск удаленных framework-следов завершились без ошибок.
- Основной интерфейс «Мои задачи» дополнен согласованными фильтрами по названию/типу и сортировкой по сроку или дате события; карточки используют фиолетовый макет и красный цвет просрочки.
- Реализованы выбор исполнителей и подзадач при создании, сохранение отметок подзадач, запрет завершения задачи до выполнения всех подзадач и исключение задач, назначенных только себе, из «Выдано мной».
- Автоматическое состояние события после даты события, возврат до блокировки чата и отказ в возврате после блокировки проверены отдельным контейнерным сценарием.
- После пересборки образа пройдены `scripts/smoke.py`, `scripts/smoke_auth.py`, `scripts/smoke_admin.py`, `compileall`, рендеринг всех Jinja-шаблонов и `git diff --check`.
- Основная доска приведена к макету: вкладочная навигация, белые внутренние блоки карточек на фиолетовом фоне, отдельные колонки сроков/дат, фильтры без отдельной кнопки и адаптивная мобильная раскладка.
- Введена роль-зависимая навигация: «Выдано мной» и создание доступны только пользователям с соответствующими разрешениями; преподаватель/куратор видит личную доску без этих действий. Проверено контейнерным HTTP-сценарием.
- Профиль показывает активность и назначенные роли; ролевые проверки также применяются к прямым URL создания и просмотра выданных заданий, а не только к кнопкам интерфейса.
- Экран создания и редактирования задачи приведен к отдельному макету: Comfortaa для заголовков, Roboto для текста, раздельные московские дата/время, мультивыбор исполнителей и управляемый список подзадач.
- Автор карточки видит независимый статус каждого активного и отозванного исполнителя; редактирование автора меняет общие поля и набор исполнителей, не смешивая персональные отметки подзадач.
- Добавление/изменение/удаление подзадач при редактировании сохраняет стабильные идентификаторы и сбрасывает выполнение только затронутых активных назначений; изменение текста, описания и сроков прогресс не сбрасывает.
- Контейнерный сценарий проверил назначение нескольким исполнителям, просмотр автором их статусов, редактирование общих полей и отзыв одного исполнителя при сохранении второго.
- Профиль обновлен по утвержденному макету: сведения об учетной записи, роли с пояснением о назначении администратором и встроенная форма смены пароля с переключателями видимости.
- HTTP smoke-сценарий профиля проверил авторизованный рендер ФИО, почты, ролей, формы смены пароля и всех переключателей видимости; существующий smoke авторизации подтвердил фактическую смену пароля и отзыв сессии.
- Добавлена вкладка «Система» для защищенной системной роли администратора: список и приглашение пользователей, удаление с очисткой проверенных связей, редактирование ролей, прав и групп, состав участников и подтверждение удаления в браузере.
- Добавлены пустые роли и группы с запретом удаления непустых объектов; системная роль администратора защищена от назначения, редактирования и удаления.
- При создании задачи/события можно выбрать пользователей, роли и группы; источники разворачиваются в активных подтвержденных пользователей один раз, дубликаты объединяются, а последующие изменения состава не меняют существующие назначения.
- `scripts/smoke_system.py` проверяет системный интерфейс, права роли, управление группой, дедупликацию, фиксацию исполнителей, раздельное удаление назначения/авторской задачи и удаление пустых роли/группы.
- Расширенный прогон дополнительно подтвердил запрет обычному пользователю на раздел «Система», защиту системной роли администратора, запрет административных прав для пользовательской роли, отклонение дублей и удаление непустых ролей/групп; после прогона временные записи отсутствуют.
- Финально проверены `compileall`, `git diff --check`, `node --check static/js/forms.js`, рендеринг всех Jinja-шаблонов, `pip check`, healthcheck и полный набор smoke-сценариев.
- Вкладка «Система» разделена на подкладки «Пользователи» и «Права»: управление сотрудниками и группами находится в первой, создание/редактирование ролей и прав — во второй; smoke проверяет оба представления.
- На вкладке «Система — Пользователи» список групп теперь работает как выбор: выбранная группа подсвечивается, отображается только её карточка управления, а выбор сохраняется после операций с пользователями и участниками группы. Контейнерный `smoke_system.py` проверяет отображение одной выбранной группы среди двух.
- Раздел «Система — Права» приведен к макету с полноширинной карточкой каждой роли: название и права сохраняются одной кнопкой «СОХРАНИТЬ», удаление роли отключено для непустых ролей, а системная роль администратора отображается как защищенная. Объединенное сохранение и запрет удаления непустой роли проверены `smoke_system.py`.
- Карточка просмотра приведена к макету: отдельный статус и просроченный цвет, дата/время срока, интерактивные чекбоксы исполнителя, блокировка завершения до выполнения всех подзадач и персональное скрытие задачи исполнителем без удаления его прогресса; для задач не показывается поле даты события. Smoke проверяет HTML карточки, отключенную кнопку при незавершенных подзадачах и отсутствие поля события.
- В режиме редактирования добавлена кнопка «Удалить» с диалогом выбора: владелец может скрыть объект у себя или архивировать его для всех, включая автора; глобально архивированный объект недоступен в карточке и чате, а неизменяемая история сообщений сохраняется.
- Поля «Дата события» и «Время события» теперь скрыты для типа «Задача» в формах создания и редактирования; переключение типа на «Событие» показывает их, а возврат к задаче очищает `event_at`. Smoke проверяет оба состояния формы.
- Верхняя область карточек задач и событий (тип, название и описание) сделана одной ссылкой на карточку; чекбоксы подзадач и кнопки действий остаются отдельными интерактивными элементами. Наличие области проверено `smoke_admin.py`, синтаксис всех 14 Jinja-шаблонов разобран в контейнере.
- Кнопки «Создать задачу», «чат», «Готово» и «Вернуть» приведены к общей геометрии и шрифту кнопок формы создания; для действий сохранено различие primary/secondary (заливка/контур). Рендер классов чата проверен `smoke_admin.py`, остальные smoke-сценарии также пройдены.
- Для адаптивной ширины до 1200px навигационные подписи и вкладки переносятся внутри кнопок; системная страница переходит в одноколоночную раскладку уже до 1400px с отдельной сеткой групп, а при ширине до 760px сетки дополнительно складываются в один столбец. Jinja и все контейнерные smoke-проверки после изменения пройдены; визуальная проверка в браузере остаётся непроверенной.
- Для кастомных выпадающих списков исполнителей, ролей и групп добавлено закрытие по клику вне списка и по `Escape`; общий smoke проверяет, что актуальный `forms.js` с обработчиком доступен через приложение.
- Исправлено удаление из формы редактирования: диалог удаления вынесен за пределы внешней формы, поэтому кнопка «Удалить у всех исполнителей» отправляет именно `/workitems/{id}/delete/`, а не повторно сохраняет карточку. Smoke проверяет отсутствие вложенной формы и фактическое архивирование задачи/события.
- Исправлено удаление пользователя с выполненными подзадачами: перед удалением его назначений очищается `workitems_subtaskprogress`, иначе внешний ключ PostgreSQL вызывал HTTP 500. `smoke_system.py` и отдельный регрессионный сценарий проверяют удаление назначения с прогрессом.

### Не проверено

- полный browser regression suite;
- миграция старых данных и старых сессий;
- production HTTPS/SMTP;
- удаление автора задачи вместе с сообщениями и аудитом в отдельном HTTP-сценарии;
- конкурентные конфликты, квоты и полная матрица аудита;
- полный browser regression suite и визуальная проверка в реальном браузере (скриншотный diff не выполнялся);
- точная визуальная проверка шрифта Comfortaa/Roboto зависит от доступности внешнего Google Fonts в браузере;
- пиксельное сравнение профиля с макетом и интерактивная проверка переключателей в реальном браузере не выполнялись; проверены HTML-рендер и JavaScript-синтаксис;
- визуальная browser-проверка вкладки «Система» и ручная проверка всплывающего подтверждения удаления не выполнялись; smoke проверяет серверные действия и наличие `data-confirm-delete` в шаблоне;
- визуальная browser-проверка новой карточки просмотра и ручная проверка кликов по чекбоксам не выполнялись; smoke проверяет HTML, серверное сохранение отметок и ограничения завершения;
- расширенные права вне проверенных административных ограничений, квоты, аудит и конкурентные конфликты.
